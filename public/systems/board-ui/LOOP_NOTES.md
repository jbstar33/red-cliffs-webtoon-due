# board-ui 2차 개선 루프 기록

## Loop 1 — 인물 아이콘에서 사건 장면으로

문제:

- 기존 초상은 인물별 장비가 달라도 정면 흉상 골격이 같아 작은 카드에서 클립아트처럼 보였다.
- 배경 문양은 상징 수준이라 장판교·합비·적벽 같은 인물의 대표 사건이 읽히지 않았다.
- 얼굴과 갑옷이 단색 면 위주라 전경과 배경의 깊이 차이가 약했다.

개선:

- 19명 전원에 `scene`, `facing`, `tilt`를 지정하고 서로 다른 역사 장면을 절차적으로 구성했다.
- 장판교 다리와 추격 기병, 오장원 천막과 등불, 합비 성문과 돌격대, 적벽 화선, 호뢰관과 적토마 등 원·중·근경 레이어를 추가했다.
- 좌우 어깨 크기가 다른 3/4 포즈, 두 팔과 손·소매·손목 보호대, 무기 그립을 추가했다.
- 얼굴과 전포에 암부·중간톤·광부를 분리하고, 붓결 32회와 종이 섬유 10줄을 카드별 시드로 생성했다.

검증:

- `node --check public/systems/board-ui/index.js` 통과.
- board-ui 기존 테스트 6개 통과.

남은 문제:

- 상세 패널의 고정 4줄 제한이 긴 능력 문장을 생략할 수 있다.
- 키워드가 이름만 나열되고 평문 정의가 없다.

## Loop 2 — 전체 문장 보존과 전술 용어 설명

문제:

- 기존 의미 단위 래퍼가 공백 뒤 토큰을 건너뛰어 사마의 능력이 `출전: 줍니다. 출전: 얻습니다.`처럼 훼손됐다.
- 상세 능력이 4줄에서 잘렸고, `돌진`, `수호`, `방패`는 정의 없이 나열됐다.
- 작은 손패도 전체 텍스트를 직접 축약해 card-data가 제공할 수 있는 짧은 문구를 활용하지 않았다.

개선:

- 토크나이저를 모든 한국어 단어와 구두점을 순서대로 보존하는 방식으로 교체했다.
- 상세 패널을 19→16px까지 실제 높이에 맞춰 선택하는 동적 레이아웃으로 바꾸고, 능력은 최대 99줄 전체 래핑 입력으로 계산한다.
- `출전:`, `죽음:`, 전투 키워드는 능력 본문에서 굵고 진한 색으로 렌더한다.
- 키워드마다 색상 칩과 한 줄 이상의 평문 정의를 배치한다. 카드 또는 런타임 컨텍스트가 정의를 제공하면 우선 사용하고 로컬 정의는 폴백으로만 사용한다.
- 손패는 `summaryText`가 있으면 이를 2줄 티저에 사용하고 상세는 항상 원래 `text`를 사용한다.
- mock의 손패 9장, 양쪽 전장 5장씩으로 19명 전원이 동시에 등장하도록 구성하고 실제 카드 문구를 넣었다.

검증:

- 사마의의 `무작위 적 하나에게 피해를 2`와 `방어도를 2` 구절 및 전체 무공백 문자열 동일성을 자동 검증한다.
- `node --check` 통과.
- board-ui 테스트 7개 전부 통과.

남은 문제:

- 작은 얼굴에서 눈과 코가 여전히 기호적으로 보일 수 있어 턱형·광대·눈꺼풀·코 측면 실루엣을 인물군별로 더 나눌 필요가 있다.

## Loop 3 — 얼굴 조형, 전경 깊이, 상호작용 회귀

문제:

- 작은 초상에서 원형 얼굴과 점눈이 남아 인물의 나이·성격·골격 차이가 약했다.
- 상세 패널 아래의 턴 종료·영웅·덱 클릭 영역으로 포인터가 관통할 수 있었다.
- X/Escape로 상세만 닫으면 첫 클릭에서 함께 준비된 출전·공격 선택이 화면에서 숨을 수 있었다.
- 9~10장 손패가 플레이어 체력 보석과 마나 패널을 덮었다.
- 기존 mock 화면 한 장만으로 19명 전원의 손패 크기와 확대 크기를 동시에 비교하기 어려웠다.

개선:

- 19개 얼굴 프로필에 턱 폭·턱 길이·광대·코 돌출·눈매·피부톤·연령을 각각 지정했다.
- 타원 얼굴을 측면 코가 돌출된 3/4 경로로 교체하고 상·하 눈꺼풀, 홍채 호선, 콧날·콧방울, 광대선, 입술 하이라이트, 연령별 주름을 추가했다.
- 긴 수염·거친 수염·각진 수염에 7~11가닥의 서로 다른 곡선 결을 넣었다.
- 림라이트와 장면별 전경 불티·꽃잎·빗줄기·먼지층을 추가했다.
- compact 초상은 관문·말·배·불길 등 2~3개의 큰 덩어리만 남겨 96×62에서도 사건 실루엣이 뭉개지지 않게 했다.
- `출전`과 `유언`을 abilities/text에서 파생해 `발동 · 키워드` 정의 행에 포함하고, 죽음 발동 표기는 화면에서 `유언:`으로 통일했다.
- 고정 패널 전체에 `inspection-panel` hit를 깔고 X hit를 그 위에 두었다. 패널 클릭은 소비하며 X/Escape는 상세와 행동 선택을 함께 닫는다.
- 손패 뒤에 가려지던 플레이어 영웅과 마나를 손패 이후 다시 그리고, hover·선택·drag 카드는 마지막에 한 번 더 그린다.
- `mock.html?gallery=1`에 19명 전원의 실제 손패 아트 96×62와 상세 아트 250×126을 두 열로 렌더하는 contact sheet를 추가했다.

검증:

- trigger 파생, `유언` 통일, 패널 hit 순서, selection 해제, 손패/영웅/마나 z-order를 각각 자동 검증한다.
- `node --check` 통과.
- board-ui 테스트 10개 전부 통과.

잔여 위험:

- Canvas 절차적 초상은 수작업 상용 일러스트만큼 미세한 붓 터치와 해부학적 손 디테일을 제공하지는 않는다.
- 갤러리의 전체 높이는 의도적으로 길며 검수 전용 URL에서만 스크롤한다.

### Loop 3b — 실브라우저 contact sheet 회귀

문제:

- 940×3076 단일 Canvas가 일부 브라우저 compositor에서 상단 구간을 반복해 19명을 신뢰성 있게 캡처할 수 없었다.
- 공통 머리·투구 하단 면이 눈높이까지 내려와 여러 인물이 검은 안대를 쓴 것처럼 보였다.

개선:

- gallery를 2열×10행으로 재배치해 940×1634로 줄였다. 각 인물 셀 안에 HAND 96×62와 DETAIL 250×126이 함께 있으므로 19명을 한 번씩 비교할 수 있다.
- 머리카락과 일반 투구·봉시관의 하단을 눈썹 위로 올렸다. 눈꺼풀과 홍채 호선은 모든 profile에서 노출된다.

검증:

- gallery의 열·행·높이 계산과 눈 영역을 가리던 기존 hairline 좌표의 부재를 자동 검증한다.
- board-ui 테스트 10개 전부 통과.

## Loop 4 — 한 장 검수와 전술 정체성

문제:

- 2열×10행 contact sheet도 일부 full-page 캡처 경로에서 세로 반복 가능성이 남았다.
- 카드 능력의 규칙은 읽히지만 “이 카드를 어떤 목적으로 쓰는가”를 상세 상단에서 즉시 파악하기 어려웠다.

개선:

- gallery를 3열×7행, 1320×1160으로 바꿨다. 각 셀의 HAND/DETAIL 비교 크기는 유지하면서 한 장 캡처 높이를 1200 미만으로 낮췄다.
- 상세 상단의 진영·역할 아래에 `전술 · {tactics.identity}` 금색 pill을 한 줄로 추가했다.
- 전술 identity는 접근성 상세 낭독에도 포함했다. plan/combo/counter는 패널 과밀을 막기 위해 읽거나 렌더하지 않는다.

검증:

- 3열 gallery 높이 계산과 tactics identity 전용 렌더 계약을 자동 검증한다.
- `node --check` 통과.
- board-ui 테스트 11개 전부 통과.
- ESLint 오류 0개. 기존 파일의 미사용 레거시 경고만 남는다.

## Loop 5 — 19인 회화형 카메라와 다단계 채색

문제:

- 장면은 달라도 얼굴이 동일한 정면 흉상, 굵은 금색 외곽, 웃는 선입으로 반복되어 평면 벡터 스티커처럼 보였다.
- DETAIL 그림 위의 두 글자 이름 워터마크가 얼굴과 사건 배경을 가렸다.
- 관우 적면·하후돈 안대·여포 봉시관 같은 표식 외에는 이름을 가렸을 때 인물 판별력이 부족했다.

개선:

- 19개 `PORTRAIT_PAINT_PROFILES`에 yaw, headX/headY, lean, scale, expression, accent를 개별 지정했다.
- 피부를 암부·반사광·중간톤·광대 온색·이마 점광의 5단계로, 전포를 그림자·기본색·림라이트·재질 반사의 4단계로 칠했다.
- DETAIL에는 58회, HAND에는 14회의 시드 고정 불규칙 붓결을 적용하고 흐린 대기층·원경·비네트를 분리했다.
- 큰 이름 워터마크를 완전히 제거했다. HAND는 배경 사건의 알파를 낮추고 얼굴/무기 halo를 높이는 별도 LOD를 사용한다.
- 적면 장수, 거친 수염, 흰 투구, 백우선/흑우선, 안대와 흉터, 쌍극, 금관, 방울, 여성 궁수, 봉황 깃을 이름 없이 읽히는 큰 실루엣으로 재구성했다.

## Loop 6 — 수염·진영 재질·작은 카드 대비

문제:

- 투구 아래 눈이 어두운 장비·전위·감녕·여포는 HAND에서 검은 덩어리로 뭉쳤다.
- `trim`과 `stubble` 수염이 모두 삼각형으로 보여 유비·손권·여몽·감녕 등의 얼굴 하단이 반복됐다.
- 위 진영 중 전위·장료·곽가의 흑철/기병 청색/죽간 황색 재질 차이가 약했다.

개선:

- 투구 그림자 인물에는 눈꺼풀과 콧대 림라이트를 추가하고 HAND 얼굴 halo를 강화했다.
- 수염을 유비의 갈라진 수염, 손권의 왕실 뾰족 수염, 장료의 바람 휩쓴 수염, 여몽의 가는 책사 수염, 사마의의 좁은 염소수염, 감녕/하후돈의 짧은 털 자국으로 분기했다.
- 전위는 저채도 흑철, 장료는 청색 기병 갑주, 곽가는 창백한 피부와 죽간 황색을 주색으로 분리했다.

## Loop 7 — 손·의복·얼굴면의 마네킹 제거

문제:

- 공통 원형 주먹과 직선 팔, 반복 수평 갑옷 띠가 인물을 마네킹처럼 보이게 했다.
- 눈·코·입 선이 피부 명암과 분리되어 떠 보이는 경우가 있었다.

개선:

- 손을 소매 cuff 쐐기, 손등, 엄지, DETAIL 손가락으로 분해했다. 책사/궁수/무장 grip과 근·원경 팔 굵기를 달리했다.
- 의복을 중갑 갑찰, 왕실 V깃과 비단, 기병 chevron/rivet, 도적 교차 strap, 책사 천 주름과 겹깃으로 나눴다.
- 눈구멍 반그림자 안에 눈썹·눈꺼풀을 묻히고 콧볼 점광과 광대의 짧은 반사광을 더했다.
- 전위와 여포의 HAND halo를 한 단계 더 높여 눈·깃·극의 핵심 대비를 보존했다.

## FX/UI 단일 소유권과 수호 차단 경로

- `hero:damage`, `minion:damage`, `attack:hit`, `effect:trigger`, `turn:start`의 즉시 연출은 `fx-animation`만 소유하도록 board-ui의 피해 링·계략 링·턴 배너를 제거했다.
- board-ui는 최종 승패 모달과 재시작 버튼만 소유하고, 치명타 접촉을 가리지 않도록 `game:end` 뒤 900ms 후 모달을 공개한다.
- 수호가 있을 때 영웅/비수호 적을 누르면 붉은 비합법 강조는 유지하되 `ATTACK`을 규칙 엔진에 전달해 `blockedByGuard`/`action:invalid` 피드백이 실제 사용자 경로에서 발생한다.

최종 자동 검증:

- `node --check public/systems/board-ui/index.js` 통과.
- board-ui 테스트 14개 전부 통과.
- `npx eslint public/systems/board-ui/index.js public/systems/board-ui/board-ui.test.mjs` 경고·오류 0개.

## Loop 8 — 두개골 기반 얼굴과 장면 광원

- 6개 두개골 기반(`oval-ruler`, `long-scholar`, `square-warrior`, `lean-youth`, `angular-veteran`, `heart-archer`)을 만들었다.
- 19인 전원에 `templeWidth`, `faceLength`, `jawAngle`, `chinPoint`, `browY`, `eyeSpacing`, `mouthWidth`, `earY`, `asymmetry`를 지정하고 얼굴 경로·눈·귀·입 배치에 직접 연결했다.
- 장식과 수염을 제외해도 유비/조조/손권과 제갈량/사마의/곽가의 얼굴 골격이 겹치지 않게 했다.
- 19개 장면 프로필에 `keyAngle`, `keyTemp`, `keyStrength`, `rimColor`, `bounceColor`를 추가했다.
- 같은 광원 벡터를 얼굴 피부, 전포, 관모, 무기에 공유해 부위마다 하이라이트 방향이 달라지던 문제를 해소했다.

## Loop 9 — 재질 반응과 표정 기하

- `MATERIAL_PROFILES`를 비단, 칠갑찰, 생철, 가죽, 목재, 깃털의 6종으로 나눴다.
- 각 재질의 specular 폭, 거칠기, 결 밀도, 봉제선, 모서리 마모를 절차적으로 렌더한다.
- 전포/갑주/관모는 실제 경로로 clip한 뒤 재질을 입히고, 무기 자루는 목재 결, 칼날은 생철 반사, 부채는 깃대와 깃가지로 분리했다.
- 19개 표정 기하가 눈썹 경사, 눈 벌어짐, 입꼬리 기울기·곡률, 콧볼 높이를 각각 구동한다.
- HAND에는 촉의 호, 위의 마름모, 오의 물결, 군웅의 사선이라는 한 가지 진영 형태 문법만 남겨 96×62에서 과밀 없이 진영을 구별한다.

최종 검증:

- board-ui 테스트 21개 전부 통과.
- `node --check` 통과.
- board-ui index/test ESLint 경고·오류 0개.
- `gallery=1`의 19인 HAND/DETAIL 전체 육안 검수와 브라우저 console 0 확인 완료.

## Loop 8 — 전장 사건성·영웅 지휘관 메달리온

문제:

- 실제 게임의 양쪽 영웅이 검은 원과 작은 얼굴 점으로만 보여 카드 초상과 품질 격차가 컸다.
- 빈 전장은 어두운 지도 선 외에 사건이 없어 적벽 전투라는 장소성이 약했다.

개선:

- 초기화 때 한 번만 래스터화하는 절차적 메달리온을 추가했다. 연합군은 옥·금속·비단·개방형 투구, 북방군은 흑철·홍칠·안면 갑주·털 장식으로 네 단계 명암과 재질을 분리했다.
- 영웅 rim은 현재 턴, 선택 가능한 공격 대상, 피해 접촉 순간, 방어도 보유 상태를 서로 다른 색과 굵기로 표시한다.
- 원경 절벽, 중경 수군 함선과 적벽 수면, 근경 군기·화톳불·등롱을 추가했다.
- 수면 반사·연기·등롱·군기만 `now` 기반으로 미세하게 움직이며, `prefers-reduced-motion`에서는 완전히 정지한다. 환경 actor와 영웅 그림은 초기화 때 한 번 생성하며 프레임 경로에서 gradient를 만들지 않는다.

## Loop 9 — 규칙 상태와 FX 접촉의 시각 동기화

문제:

- 규칙 엔진의 피해·죽음 상태가 FX 접촉보다 즉시 먼저 보였고, 빠른 연속 입력은 공격 연출을 겹치게 했다.

개선:

- `attack:start`에서 보이는 영웅·장수·체력·방패 snapshot을 저장한다. 규칙 상태는 즉시 진행하지만 화면은 365ms 접촉 전까지 pre-hit 상태를 유지한다.
- 공격 영웅 피해 숫자와 방어도는 365ms, 직접 효과는 125ms latch 뒤 새 값으로 전환한다. 토큰별 중복 처리를 막고 rim·health gem 피해 pulse도 같은 접촉 시점에 시작한다.
- 죽은 장수는 620ms까지 클릭되지 않는 dying ghost로 남아 FX의 죽음 cue와 함께 잿가루로 사라진다.
- 공격은 700ms, 카드 출전은 560ms 동안 다음 전장 행동을 잠근다. ESC, 음소거, 카드 설명 확인은 계속 가능하다.
- AI의 다음 공격이 앞 연출보다 먼저 규칙상 처리되더라도 `before`/`after` snapshot 큐가 화면 표시를 직렬화한다.

검증:

- `node --check public/systems/board-ui/index.js` 통과.
- board-ui 테스트 18개 전부 통과.
- `npx eslint public/systems/board-ui/index.js --max-warnings=0` 통과.

## Loop 10 — 잠금 상태와 방어도 접촉 미세 조정

- 연출 잠금 중 손패와 공격 가능 광휘를 비활성화하고 턴 버튼을 `전투 처리 중 / RESOLVING`으로 바꿔, 눌러도 되는 것처럼 보이는 모순을 제거했다.
- 잠금 중에도 카드 클릭 설명, ESC, 음소거는 유지한다.
- 피해가 방어도에 전부 흡수된 경우 붉은 체력 pulse 대신 푸른 방어도 rim/gem pulse가 접촉 시점에 발생한다.
- 공격 시작의 잠금 상태를 스크린리더 live region에도 알린다.
- 부모 실브라우저 검수에서 기본/1366×768/768×720 겹침 0, console 0을 확인했다. 직접 피해는 약 40ms 이전 체력 유지→155ms 새 체력, 전투 피해는 약 40ms 이전 체력 유지→390ms 새 체력으로 측정돼 125ms/365ms 접촉 계약과 일치했다.

## Loop 11 — 내부 키 차단·검사 패널 수명·5장 비차단 레일

- 규칙 엔진의 reason/outcome을 `UX_CODE_MESSAGES`에서 한국어 행동 문구로 바꾸며, 미래의 영문·snake_case 키도 안전한 한국어 기본 문구로 대체한다.
- 통합 런타임에서는 번역문을 동일 이벤트 payload에 기록해 FX 배지와 접근성 안내가 같은 문구를 사용한다. FX 배지가 있는 화면에서는 중앙 토스트를 중복 표시하지 않고 독립 목업에서만 토스트를 유지한다.
- 검사 중인 카드를 `instanceId`로 손패와 양측 보드에서 재탐색한다. 카드가 손패에서 전장으로 이동하면 위치를 갱신하고, 출전·공격·사망 확정 대상이거나 상태에서 사라지면 패널을 닫는다.
- 패널 폭을 318px로 줄이고 5장 보드의 좌우 끝과 각각 14.5 logical px 간격을 확보했다. 980×856과 768×720 축척에서도 카드 hitbox를 침범하지 않는다.

## Loop 12 — 방패 소모·무작위 규칙 스캔 문법

- 방패 키워드와 실제 `shield` 상태를 분리해 활성 방패만 청색 외곽 광휘를 보인다.
- 방패가 소모되면 회색 방패, 대각 파손선, 균열을 표시하고 상세 키워드를 `방패 소모`로 바꾼다. presentation snapshot의 접촉 전후 상태에도 그대로 연결된다.
- `무작위` 규칙에는 보라·금색 주사위 표식을 붙이고 작은 카드와 상세 설명의 `무작위` 단어를 별도 굵기·강조색으로 그린다.
- raw-key, stale 이동/삭제, 두 목표 뷰포트 패널 간격, 방패 활성/소모 상태를 포함한 board-ui 회귀 테스트 27개가 통과했다.
